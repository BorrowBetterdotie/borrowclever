# /data

Source-of-truth JSON for all rate data. Edit here, run `node build.cjs`, then diff and commit.

## Files

| File | Purpose |
|------|---------|
| `loans.json` | All personal loan products, sorted by APR ascending |
| `cards.json` | Credit card products |
| `savings.json` | Deposit & savings account products (banks, State Savings, credit unions, EU digital banks/marketplaces), grouped by `accountType` |

## Loan record fields

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Stable slug, e.g. `ptsb-personal` |
| `lender` | string | Display name |
| `product` | string | Product name |
| `icon` | string | Abbreviation shown in icon circles |
| `iconCls` | string | CSS class for icon colour |
| `apr` | number | Effective annual rate (%) — this is the key comparison figure |
| `rateType` | string | `"Fixed"` or `"Variable"` |
| `typeNote` | string | Short feature note shown on homepage card, e.g. `"No conditions"` |
| `green` | boolean | Marks green/energy loan rows |
| `seai` | boolean | Requires SEAI home energy grant |
| `creditUnion` | boolean | Credit union product |
| `homepage` | boolean | **Featured on the homepage mini-table** — see below |
| `notes` | string | Footnote text in the full loans table |
| `badgeCheapestOverall` | boolean | Shows "Cheapest overall" badge |
| `badgeBestStandard` | boolean | Shows "Best standard rate" badge |

## Savings record fields

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Stable slug, e.g. `aib-online-saver` |
| `lender` | string | Display name |
| `product` | string | Product name |
| `accountType` | string | One of `"Instant access"`, `"Regular saver"`, `"Notice account"`, `"Fixed term deposit"`, `"State savings"`, `"Credit union"` — drives table grouping in `savings.html` |
| `aer` | number \| null | Annual Equivalent Rate (%) — the key comparison figure within each `accountType` group. `null` for Prize Bonds, which pay no fixed rate |
| `rateType` | string | `"Fixed"`, `"Variable"`, or a short description for non-standard products |
| `term` | string | Notice period / lock-in / access description |
| `minDeposit` / `maxDeposit` | string | Free text — deposit limits vary too much across product types for a single numeric field |
| `taxAtSource` | boolean | `true` if DIRT (33%) is deducted automatically; `false` if interest is paid gross and must be self-declared. State Savings products are tax-free regardless of this flag |
| `protection` | string | Which deposit guarantee scheme (or sovereign guarantee, for State Savings) applies |
| `crossBorder` | boolean | Marks non-Irish EU providers/marketplaces — styled as `row-cross` in the table |
| `creditUnion` | boolean | Credit union product — styled as `row-cu` |
| `notes` | string | Footnote text in the full savings table |
| `badgeHighestRate` / `badgeBestRegularSaver` / `badgeStateBacked` / `badgeTaxFree` / `badgeNoConditions` | boolean | Table badges |
| `source` | string (optional) | Provider URL used to verify the rate, where confirmed during research |

## Homepage hero generation

`index.html`'s hero panel and "Switch and save" callout are generated by `build.cjs` — **do not edit those sections by hand**.

- The featured set is the four loans with `"homepage": true` in `loans.json`: currently `ptsb-personal`, `boi-personal`, `anpost-personal`, `aib-personal`.
- The saving figure derives automatically: `totalInterest(aib-personal) − totalInterest(bestFeatured)`, using the effective monthly rate formula `i = (1 + APR/100)^(1/12) − 1` over 60 months on €10,000.
- Interest figures are not stored — they are recomputed on every build.

## Important: comparison tables are hand-authored, not generated

`build.cjs` only injects JSON-LD, the "last verified" date, and (for `index.html`) the hero saving figure — it does **not** generate the `<tr>` rows in `loans.html`, `cards.html`, or `savings.html`. Those tables are hand-written HTML that must be kept in sync with the JSON files manually. When you add or change a product, update both the JSON file (source of truth, and what feeds `/api/v1/*` via `build-api-data.mjs`) and the corresponding `<tr>` block in the HTML page.

## Update workflow

1. Edit the relevant fields in `loans.json` / `cards.json` / `savings.json`, and update the matching `<tr>` row(s) in `loans.html` / `cards.html` / `savings.html` by hand.
2. Update `meta.last_full_review` in the JSON file you changed.
3. Run `node build.cjs` from the repo root (note: `.cjs`, not `.js` — the repo's `package.json` sets `"type": "module"`, so a plain `.js` file using `require()` won't run).
4. Review the diff — JSON-LD blocks and "last verified" dates will update; `sitemap.xml` and (for loans) the `index.html` hero numbers regenerate too.
5. Commit and open a PR.

## Automated rate checking

A GitHub Actions workflow (`.github/workflows/rate-check.yml`, fortnightly cron) runs three independent, read-only checkers that scrape published provider pages and diff them against the JSON files — **none of them write to the JSON files**; a human still reviews and edits `loans.json` / `cards.json` / `savings.json` by hand per the workflow above.

| Script | Covers | Source list |
|---|---|---|
| `scripts/check-rates.mjs` | Loans | `lenders.csv` |
| `scripts/check-rates-ccpc.mjs` | Loans (cross-check against CCPC's compare tool) | n/a — queries `compare.ccpc.ie` directly |
| `scripts/check-rates-savings.mjs` | Savings & deposit accounts | `data/savings-lenders.csv` |

Each run writes a dated snapshot and changes report to `rates/` (e.g. `rates/savings-rates-2026-09-09.csv`, `rates/SAVINGS-CHANGES-2026-09-09.md`) and, on parse failures, the raw HTML it couldn't extract a rate from to `rates/debug/` for manual inspection.

`data/savings-lenders.csv` only lists products with a **confirmed, real** source URL — of the 29 products in `savings.json`, 3 (Trading212, Bunq, FCM Bank) don't have one yet and are intentionally left out of automated checking rather than guessed. Add a row (and the matching `source` field in `savings.json`) once a real product-page URL is confirmed for one of them.
